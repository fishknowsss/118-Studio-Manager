# 项目焦点与项目工作台重构设计

## 背景与目标

当前项目焦点、项目总览、项目时间轴和项目详情分别承担展示、编辑或查看职责。同一个“点击项目”在不同入口产生不同结果，且详情首屏没有把下一步行动放在最前面。本次重构将它们收敛为统一的项目工作台体验。

目标是让用户在任一入口快速判断项目优先级、下一步行动、交付风险和当前进度，并以最少操作进入可执行的任务与排期管理。

## 体验原则

- **查看优先，编辑明确可见。** 点击项目一律进入工作台；编辑、状态变更和删除为独立操作，不依赖右键或 hover。
- **行动优先于统计。** 首屏先展示下一节点、下一任务和阻塞风险，统计信息作为辅助判断。
- **一个主日期。** 交付日期是用户可见的主 deadline；结束日期只在不同于交付时作为排期辅助，旧 `ddl` 保持兼容但不作为主要界面概念。
- **同一项目、同一心智模型。** Dashboard 焦点、项目卡片、项目时间轴和搜索结果使用一致的项目摘要、状态语言和详情入口。
- **所有设备可操作。** 关键操作可键盘到达、具备可见焦点；移动端操作不依赖 hover，焦点区保留最小时间上下文。

## 信息架构与交互

### Dashboard 项目焦点

保留固定高度的四行时间轴，避免侵占今日工作区。每行包含项目名、阶段、进度、负责人、交付日期和一个行动信号：

- 受阻时优先显示受阻任务数量；
- 否则显示最近的下一节点或下一待办；
- 无日期的项目显示明确的排期缺失状态。

焦点区标题使用语义化按钮，点击打开项目总览。时间轴行打开对应项目工作台。键盘焦点和 hover 使用同一层级的视觉反馈；窄屏保留“今天”和交付语义，不依赖完整横轴。

### 项目总览

项目总览是筛选和定位入口，而不是编辑入口。工具栏提供关键词、状态、优先级和视图切换。卡片与时间轴均可打开项目工作台；卡片提供显式的查看、状态和编辑操作。无筛选结果和无项目数据分别使用不同的空状态与恢复操作。

时间轴提供“今天”定位与项目选择，避免只有静态展示。状态快捷操作提供可触控的显式入口，右键菜单仅作为补充。

### 项目工作台

项目详情重排为四个连续区块：

1. **项目摘要与行动**：状态、优先级、交付、进度，下一节点、下一任务、受阻与逾期信号，以及新任务、编辑、完成等主要动作。
2. **排期**：开始、审查、交付、结束与备注。交付日期为主字段；保存时对旧 `ddl` 同步兼容。
3. **风险**：只在有受阻或逾期时出现，突出需要解除的任务。
4. **任务**：按执行优先级显示任务并支持既有快捷更新、编辑与删除。

弹层打开后焦点进入工作台标题或首个主要操作，关闭后返回触发元素。ProjectDialog 保持为项目元数据编辑器，不能再作为点击项目的默认结果。

## 组件边界

- `ProjectFocusTimeline`：渲染焦点摘要和打开项目工作台。
- `ProjectOverviewToolbar`：项目总览的搜索、筛选和视图控制。
- `ProjectCard` / `ProjectTimeline`：展示并通过 `onOpenProject` 进入工作台。
- `ProjectDetailPanel`：组合摘要、排期、风险、任务四个区域；不承担入口选择逻辑。
- `ProjectDialog`：项目编辑。
- selectors：生成一致的焦点、列表和时间轴模型；不在视图层重复计算任务状态。

## 数据与错误处理

- 保留现有 IndexedDB 结构和同步负载，不新增 store。
- 主日期解析统一使用 `deliveryDate > endDate > ddl`；界面以 `deliveryDate` 呈现。
- 保存日期时清除已失效的兼容 `ddl`，并在必要时与主交付日同步。
- 遇到开始晚于结束的旧数据时，在 selector 层规范化时间范围，确保 timeline 不出现负宽度或反向排期。
- 写操作继续走既有 `store.saveXxx()` / action / toast 链路；失败不得伪造成功状态。

## 可访问性与响应式

- 所有可点击区域使用 button 或 link；纯图标按钮带 `aria-label`。
- 时间轴行、总览卡片操作、筛选器、详情动作拥有 `:focus-visible`。
- 搜索保持 combobox 语义并暴露展开与活动项状态。
- 详情弹层实现焦点管理、Escape 关闭和触发点焦点回退。
- 触控设备显示卡片操作，不以 hover 作为唯一发现途径；无横向页面溢出。

## 验收标准

1. Dashboard 焦点、Dashboard 搜索、项目卡片、项目时间轴均打开同一个项目工作台。
2. 项目焦点维持四行和既有高度约束，增加行动或风险信号但不退化为大卡片。
3. 项目总览可关键词过滤，筛选空结果和数据为空的提示可区分。
4. 用户可通过键盘完成打开总览、打开项目、编辑、状态变更、关闭详情；关闭后焦点回到触发点。
5. 交付日期的更改或清空同步反映在焦点、详情、排序和项目时间轴中，不保留陈旧 deadline。
6. 新增与更新的 Vitest 覆盖入口一致性、日期规范化、焦点可访问性及项目总览交互；`npm run build` 和 `npm run test` 通过。

## 范围边界

本次不新增协作、通知、实时同步或新的数据存储模型；不修改与项目工作台无直接关系的功能。视觉和交互升级基于现有 React、TypeScript 和纯 CSS 架构完成。
